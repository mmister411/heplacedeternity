# Shared research apparatus

The apparatus examines what a witness reports experiencing. It works across Perdition, Paradise, and other reported settings. The author's decision in `../poe_register.tsv` determines whether a prospective optasiological event (POE) may enter analysis as a valid optasiological event (VOE). Testimony documents belong in the shared `../testimonies/` collection; documents and experiences are distinct units.

## Scene-based evidence

`evidence.py` maintains one location-neutral JSONL evidence store (`evidence.jsonl`, created when the first record is accepted). Records have three forms:

1. **Scene** — a coherent reported episode, linked to an accepted VOE, an acquired source artifact, and a passage/page/time anchor. A scene may contain several actions, beings, settings, and transitions.
2. **Observation** — a particular within that scene, described in its reported form. Its open-ended `aspect` might be a place, person, object, sight, smell, action, state, or attributed speech. Descriptive details stay attached to the particular: an orange fox with purple teeth is not reduced to a generic canine.
3. **Relation** — a stated or analytical relationship between scenes or observations. A proposed comparison between distinct VOEs is explicitly marked `inferred`, with its basis. It does not silently identify the two subjects as the same thing.

There are no place-specific columns or closed list of realms in these records. A named location can be reported as an observation. An unnamed setting can be described directly. An analyst may add an inferred identification, with an explicit basis. Reported speech by a captive or other encountered person is part of the scene (`attributed_speech`), not disposable narration. Only relevant experiential content is curated; introductory autobiography and incidental exclamations need not become observations.

All records have opaque permanent IDs. The evidence store contains no invented corpus totals, automatically inferred identities, or autogenerated scene boundaries. Nothing is added until a reviewer works from an actual source passage.

Run from the repository root or another directory:

```sh
python apparatus/evidence.py check
python apparatus/evidence.py list
python apparatus/evidence.py list --poe POE-000001
python -m unittest discover -s apparatus -p test_evidence.py
```

To record an actual scene and its particulars, use IDs and anchors from the source collection:

```sh
python apparatus/evidence.py scene --poe POE_ID --source ARTIFACT_ID --anchor "PAGE_OR_PASSAGE" --description "COHERENT_SCENE"
python apparatus/evidence.py observe --scene SCENE_ID --aspect "being" --mode seen --description "REPORTED_DESCRIPTION" --detail "PARTICULAR_PROPERTY"
python apparatus/evidence.py observe --scene SCENE_ID --aspect "place" --mode interpreted --assessment inferred --basis "WHY_THIS_IDENTIFICATION_FOLLOWS" --description "INFERRED_LOCATION"
python apparatus/evidence.py relate --subject OBSERVATION_ID --predicate "resembles" --object OTHER_OBSERVATION_ID --basis "SPECIFIC_SHARED_AND_DISTINCT_FEATURES"
```

`scene` and `observe` print new IDs for later use. `relate` defaults to an analytical inference; use `--assessment reported` only for a relation actually expressed within the same VOE. Source IDs come from `../testimonies/source_copy_register.tsv` or locally acquired entries in `../testimonies/source_manifest.tsv`; source-to-VOE assignment and the author's `valid` decision are enforced. Use `python poe_registry.py intake` at the repository root to audit source-copy checksums. A separate scene record need not be created for every document copy.

The store is append-only through the CLI. Review entries and source passages before committing them. A future editorial correction should preserve the superseded claim's history rather than silently change what a witness was reported to say.

## Corpus crosswalk and reconstructed passages

The inherited, source-verified observations remain in `atlas_phenomena_seed.tsv`; they are **not** bulk-copied into the new evidence store. To inspect the complete accepted corpus in the location-neutral form, run:

```sh
python apparatus/evidence.py inherited --summary
python apparatus/evidence.py inherited --poe POE-000006
```

This command revalidates the original compilation anchors and projects their witness-specific descriptions without creating another authoritative file. The existing `atlas_motif_families.tsv` remains the authoritative curated motif membership record.

`evidence.jsonl` contains an initial set of bounded, cited passages across the accepted corpus, with selected observations linked back through `legacy_ref` and cross-VOE relationships explicitly marked as analytical inference. Its `scope` labels make clear that a bounded passage does **not** establish an independent experience boundary. These records are **not** a claim of exhaustive scene segmentation or an automatically fused geography. The source work `POE-000006` contains repeated excursions in a multi-chapter work; its chapter headings are not automatically POE boundaries.

## Earlier Perdition research

The working records below are retained from the earlier Perdition-focused extraction. Their observations and categories keep that scope; they are not a generic taxonomy of Eternal Life. They have **not** been auto-migrated into scene records because the older extraction does not establish source-grounded scene boundaries.

## Working data

- `atlas_phenomena_seed.tsv`: curated, source-anchored observations with POE identifiers.
- `atlas_motif_families.tsv`: curated cross-witness motif assignments and notes.
- `Atlas_of_Perdition_Phenomena_Register.jsonl`: generated structured phenomena.
- `Atlas_of_Perdition_Second_Order_Index.tsv`: generated subclass assignments.
- `atlas_second_order.py`: curated subclass codebook and assignments.

The scene inventory, corpus survey, and evidence audits contain additional contextual findings. Retain them until their unique findings are incorporated and checked. Current POE decisions are held in the root `poe_register.tsv`.

## Regeneration

Run from this directory:

```sh
python atlas_sift.py
python build_phenomena_register.py
python atlas_second_order.py
```

The lexical CSV is produced on demand. Readable Markdown views are also optional:

```sh
python build_phenomena_register.py --views
python atlas_second_order.py --views
```

The original compilation is at `../testimonies/_intake/Experiences_1.txt`. Generation checks the source anchors and accepted POE status. The working observations, distinctions, and relationships remain subject to source-level verification.
